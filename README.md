Задача: В текущем задании нужно реализовать два компонента: <Signin /> и <Signup />
** В задаче много подзадач, поэтому решение будет последовательным

Решение:
1. Создал папку components, в ней Компонет input со всеми необходимыми по заданию стилями
2. После уточнений в чате, поправил реализацию динамического изменения стилей с <input style={}/> на подставление классно.
*Что, кстати, расстроило, т.к. решение при помощи <input style={}/> показалось намного изящьнее, т.к. выполнялись одной строчкой, а не 12-ю дополнительными классами, с одними и теми же стиля, в которых в ручную менялась одна-две цыфры. 
    Так же, с учетом уточнений в чате, стилизовал поле "Ник"
    Переделал реализацию стилей CSS-модулями (так же после уточнений в чате)
3. Добавил константы (папку, а в ней файлы и проиндексировал их) с настройками инпутов из задания, с регулярными выражениями для валидации и с сообщениями ошибок. Так же добавил передачу type в input (по умолчанию 'text')
4. Добавил 2 инпута на главную. Проверил динамические изменения при изменении пропсов. Поправил стили, чтобы при исчезании сообщения об ошибке инпут не скакал на странице.
5. Убрал звёздочку (asterisk) и ник из констант. Т.к. подумал, что логичнее будет из констант задавать значения не каждому инмуту, а добавлять, допустим, в state и уже из него передавать каждому инпуту (В том смысле, что врад ли в одной форме должны быть инпуты разного формата: один больше, один меньше один с обводкой и т.д. Хотя формы бывают разные, ну в такоем решении, в любом случае, есть возможность кастомизировать и каждый инпут отдельно и все разом через state). Это я всё к тому, что asterisk и nick либо передаются в props (тогда они имеют значение true), либо нет и можно подставлять нужные классы исходя из того передан этот пропс или не передан вообще и не обязательно выносить его значения в константу
6. Реализовал компонент <Signin />:
- Все настройки добавил в state (пока без возможности изменения, чтобы не выводилось предупреждение).
- Сделал валидацию пароля и Емейла. При вводе пароль валидируется на "неподходящие символы", либо если "слишком длинный". На "слишком короткий" валидацию сделал при отправки формы. Т.к. иначе ошибка будет вылезать сразу, как только пользователь начнет что-то вводить
По той же причине валидацию Емейла сделал при отправке формы, (чтобы ошибка не вылазила сразу, как только пользователь начал что-то вводить)
*Компонент получился огромный, позже его "разгружу", а пока займусь типизацией (давно пора)
7. Типизировал текущий код

9. Функции по валидации тоже вынес отдельно (в папку utils). Всё работает. Осталось решить вопрос с валидацией при отправке данных и обнулением Стэйта
10. Так же в папку handlers вынес функцию onSubmit (пока пустую), импортировал её в Компоненте App и передал, как pros в Компонент <Signin />.
